# アンチパターン集（やっちゃダメ）

## CEO差し戻しパターン

| パターン | 何が起きた | 教訓 |
|---------|----------|------|
| 内容短縮 | 移行作業で内容を短縮/省略 → ren激怒 | 「絶対に短縮するな」は鉄の掟 |
| 商材理解不足で設計 | 診断のCTAを商材見ずに作った → 即指摘 | 診断設計前にPR資料・商材内容を必ず確認 |
| tasks.json未読 | 起動時にtasks.json読まず「やることない」 | 起動時に必ずtasks.jsonを読め |
| 古いデータ混入 | 対応済み記事が分析に残ってた | 品質ゲートに鮮度チェック必須 |
| CEOが判断をrenに投げた | 「CIO呼んでいい？」を3回聞いた | CIO/CMO起動はCEO自律判断。renに確認取るな |
| CEOが直接作業した | weekly-reportの改修をCEO自身がやろうとした | CEOは1行もコード書くな・読むな。問題特定→CTOに振れ |
| 読み手を考えずにアウトプット | 週次報告を「タスクとして埋める」作業をした | アウトプット作成前に「読み手は誰？何を判断する？」を必ず考えろ |

## データの落とし穴

| パターン | 何が起きた | 教訓 |
|---------|----------|------|
| 処理順序バグ | find_missing_tagsとoverrideの順序逆転 → 友だち数が191人 vs 314人 | 処理順序は絶対 |
| 未収集タグ補完漏れ | analysis_engine単体使用 → 補完なし → 過少 | ダッシュボードのフルフローが正 |
| 月間換算の罠 | 3日データを÷3×31で換算 → 不正確 | 前月実績をベースラインにしろ |

## 施策設計のNG

| パターン | なぜダメ | 正しいやり方 |
|---------|---------|------------|
| 汎用CTA使い回し | ジャンルでCV導線が違う | ジャンルごとにCTA設計 |
| 1診断を全記事適用 | KWで検索意図が違う | 記事KWの検索意図から逆算して診断設計 |
| ボトムアップ思考 | 記事の良し悪しから考えてもGOALに繋がらない | GOAL→GAP→レバー→ジャンル→記事の順 |
| 選択肢を並べてrenに投げる | renの判断負荷が上がる | 推奨1本出して「GOでいい？」 |
| 数字なし提案 | 「なんとなく良さそう」は通らない | PV×改善幅=インパクトの定量根拠を添える |
| 手法から入る | ツール名で検索→前提違うデータで設計 | ユーザーの状態から始めろ |

## ファネル異常パターン

| 症状 | 原因仮説 | 最初に確認すること |
|------|---------|-----------------|
| CTR高 × FR低 | LP遷移先URL間違い、LPとPUの乖離 | 遷移先URLを実際に踏んで確認 |
| CTR低 × FR高 | PUコピーが弱い。LP自体は機能 | PUコピー変更でimp活用 |
| PVFR低 × IMPFR正常 | PU表示率の問題（読了率低い、配置悪い） | PU imp / LP PV 比率 |
| PVFR低 × IMPFR低 | PU自体の魅力不足 + 表示問題 | 両方手を打つ |
