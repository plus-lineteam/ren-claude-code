1. 全体像

今あなたが使っている既存のプロジェクトフォルダを、チームメンバーと安全に共有する仕組み。
ポイントはリポジトリを2つに分けること。あなたのコードを守りつつ、メンバーが自走できる環境を作る。

💡 「既存のプロジェクトフォルダ」とは？

あなたが普段使っているコード・ダッシュボード・Claude Code設定が入ったフォルダのこと。
例：claude-projects/ のように、複数のプロジェクトをまとめたフォルダ全体。
これをそのままGitHubに上げて共有する。新しく作り直す必要はない。

リポジトリ構成
GitHubクラウド上の共有場所
↕
既存のプロジェクトフォルダオーナーの本体 / メンバーは見るだけ
メンバー用ワークスペースメンバー専用 / 自由に使える

💡 なぜ分けるのか？

・メンバーの作業がオーナーのコードに影響しない

・メモリーやCLAUDE.mdが混ざらない

・承認フローなしでメンバーが自走できる

・GitHub無料プランでも運用できる

各PCのフォルダ構成
オーナーのPC 📁 既存のプロジェクト/ → 本体（編集・push/pull）
📁 メンバーのワークスペース/ → 確認用（pullで見る）
メンバーのPC 📁 既存のプロジェクト/ → 参照用（pullだけ）
📁 自分のワークスペース/ → 作業場（push/pull）
📄 ~/.claude/CLAUDE.md → 専用設定

既存のプロジェクト = 教科書

オーナーのコード、ダッシュボード、Claude Code設定が入ってる。メンバーは読むだけ。編集できない。

メンバー用ワークスペース = ノート

メンバーの分析メモ、レポート、メモリーが入る。好き放題使える。

2. オーナーとメンバーの違い

一目でわかる対比表。

オーナー メンバー
役割 コード開発・管理 分析・レポート・作業
既存プロジェクト ✏️ 編集できる 👀 見るだけ
ワークスペース 👀 確認用（pullで見る） ✏️ 自由に使える
CLAUDE.md 自分の設定がそのまま メンバー専用ルールを設置
データソース 自分の.env / credentials オーナーから共有してもらう
push先 既存プロジェクト ワークスペースのみ

💡 ポイント

オーナーのフォルダに対して、メンバーは読み取り専用。メンバーが何をやっても、オーナーのコードには一切影響しない。

3. オーナー側のセットアップ

STEP 1：既存のプロジェクトフォルダをGitHubに上げる

1.gitignore を作る

機密ファイルをGitHubに上げないための設定。プロジェクトフォルダ直下に作成。

.env
credentials.json
__pycache__/
node_modules/
.DS_Store

⚠️ .env と credentials.json は絶対にGitHubに上げない。パスワードと同じ扱い。

2GitHubにリポジトリ作成

  1. GitHub → 右上「+」→「New repository」
  2. Repository name を入力
  3. Private を選択
  4. 「Create repository」をクリック

3ローカルからpush

VSCodeのターミナルで：

cd ~/Desktop/your-project-folder
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/your-project-folder.git
git push -u origin main

STEP 2：メンバー用ワークスペースを作る

4フォルダ構成を作る

member-workspace/
├── MEMBER_CLAUDE.md   ← メンバー用のClaude Code設定
├── SETUP.md           ← セットアップ手順書
├── memory/            ← 学んだこと・ナレッジ
├── notes/             ← 分析メモ・気づき
└── reports/           ← 提出用レポート

5GitHubに上げて、メンバーを招待

  1. 同じ手順でリポジトリ作成 & push
  2. Settings → Collaborators → Add people
  3. メンバーのGitHubユーザー名を入力して招待
  4. 両方のリポジトリで招待する

STEP 3：データソースを共有する

6credentials.json / .env を渡す

渡すもの方法注意
credentials.jsonSlack DM / AirDropGitHubには絶対上げない
.env の値Slack DMで直接伝えるメンバーが.envを自分で作る
APIキーメンバー用を別途発行が理想共有する場合はDMで

4. メンバー側のセットアップ

1Gitをインストール（Mac）

VSCodeのターミナルで：

xcode-select --install

ポップアップが出たら「インストール」→ 数分待つ → VSCode再起動

2Git初期設定

git config --global user.name "GitHubユーザー名"
git config --global user.email "GitHubメールアドレス"

3リポジトリをクローン（2つ）

VSCode → 左の分岐マーク → 「リポジトリのクローン」

① 既存のプロジェクト（見る用）：

https://github.com/OWNER_USERNAME/your-project-folder.git

② 自分のワークスペース（作業用）：

https://github.com/OWNER_USERNAME/member-workspace.git

保存先はデスクトップでOK。

💡 2つ目のクローンは「ファイル → 新しいウィンドウ」から開く

4Claude Code設定を設置

mkdir -p ~/.claude
cp ~/Desktop/member-workspace/MEMBER_CLAUDE.md ~/.claude/CLAUDE.md

これでClaude Codeにメンバー専用のルールが適用される。

5データソース接続

  1. オーナーからもらった credentials.json をプロジェクトフォルダに配置
  2. .env.example をコピーして .env を作成、値を入力
  3. 必要なライブラリをインストール：
cd ~/Desktop/your-project-folder/対象プロジェクト
pip install -r requirements.txt

6動作確認

streamlit run app_main.py

ブラウザでダッシュボードが表示されれば完了！

5. 日常の運用フロー

オーナーがコードを更新した場合

オーナー
コードを修正して push
↓ GitHub上で更新される
メンバー
VSCodeで pull → 最新のコードが反映される

メンバーが分析・作業をした場合

メンバー
Claude Codeで分析 → 結果を member-workspace に保存
↓ commit → push
GitHub
member-workspaceが更新される
↓ オーナーが確認したいタイミングで
オーナー
member-workspaceを pull → メンバーの成果物が見れる

VSCodeでのpull / push 手順

pull（最新を取得）

左の分岐マーク → 上部「...」→「プル」
またはステータスバーの🔄マークをクリック

push（変更をアップ）

① メッセージ欄に一言書く（例：「離脱防止タグ分析」）
② 「コミット」ボタンを押す
③ 「...」→「プッシュ」

日常タスクまとめ

やること頻度
オーナーコード更新 → 既存プロジェクトにpush随時
オーナーmember-workspaceをpull → 成果確認毎日
メンバー既存プロジェクトをpull → 最新コード取得毎朝
メンバーClaude Codeで分析・作業随時
メンバー成果物をmember-workspaceにcommit → push作業後

6. セキュリティルール

⚠️ 絶対にやってはいけないこと

・.env や credentials.json をGitHubにpushする

・APIキーをメールやチャットで送る（DM限定）

・リポジトリをPublicにする

・メンバーが既存プロジェクトのファイルを直接編集する

セキュリティチェックリスト

  • リポジトリはPrivateになっているか
  • .gitignoreで.env、credentials.jsonが除外されているか
  • credentials.jsonはSlack DM等で安全に共有したか
  • メンバーのCLAUDE.mdに「既存プロジェクト編集禁止」ルールがあるか
  • GitHubに機密情報がpushされていないか

7. トラブルシューティング

❓ ソース管理で「クローン」が出てこない
→ 「ファイル → 新しいウィンドウ」で新しいVSCodeを開いてからやる
❓ 「user.name と user.email を設定しろ」と出る
→ ターミナルで以下を実行：
git config --global user.name "ユーザー名"
git config --global user.email "メールアドレス"
❓ 「ステージされてない変更がある」と出る
→ 「はい」を押せばOK。全ファイルをまとめてコミットしてくれる。
❓ credentials.jsonを置いたのにスプシに繋がらない
→ ファイルの場所を確認。プロジェクトフォルダの直下にあるか？
❓ メンバーの変更がオーナー側に影響する？
→ しない。リポジトリが別なので完全に独立。member-workspaceの変更は既存プロジェクトに一切影響なし。
❓ Xcode Command Line Toolsのダウンロードが遅い
→ 1〜2GBあるので数分〜十数分かかる。初回だけなので待つ。
