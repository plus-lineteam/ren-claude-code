ren-claude-code🧠🏢

実際に業務で使っているClaude Codeのフォルダ構造。
構造と役割、そして実際の中身まで全部公開。

この構造の考え方：AIを「毎回リセットされるチャットbot」ではなく「記憶を持つ組織」として設計。
🧠 脳 = mind.md（性格）+ knowledge/（長期記憶）+ memory.md（短期記憶）
🏢 組織 = CEO（判断）→ CIO（データ）/ CMO（マーケ）/ CTO（技術）の役割分担
🔄 学習ループ = 失敗→記録→3回で昇格→ルール化。使うほど賢くなる。

📜 会社の定款 AIが毎回最初に読むルールブック
📄 CLAUDE.md 組織構造・Memory Protocol・ルーティングルール ▶
目的：AI組織の「憲法」。どのロールを起動しても、まずこれを読んでから動く。

主な内容：
  • Mission — ノウハウ記事PVユーザーをLINE友だちに転換→ナーチャリング→間接CV
  • Organization — ren→CEO（唯一の窓口）→CTO/CIO/CMO。renはCEOとだけ話す
  • Memory Protocol — 書くトリガー6個（差し戻し/想定外データ/判断迷い/バグ/good反応/新制約）
  • 読むルール — セッション開始時にmemory.md読む、提案前にanti-patterns読む
  • Knowledge昇格 — 同じ教訓が3回→knowledge/にルール化

    •

    • 
        
  • renへの報告は1回。質で勝負
    • 
        
  • 差し戻しは具体的に（「XをYに変えて」）
    •

    • 
        
  • 判断をrenに投げない。データで決めて「GOでいい？」と聞く
    • 
        
  • GOALに反するならrenにも反論する
    • 
      

      CXO判断軸（4つ）：ユーザープール拡大？/ 間接CVとして正しい？/ 期限？/ 本当に必要？

    学習ループ — 使うほど賢くなる仕組み
  


  

    

      🔄
      学習ループの全体像
      日次→週次→月次の3層サイクル
      ▶
    

    


失敗・発見が起きる
    ↓
memory.md に記録（短期記憶）
    ↓
同じ教訓が 3回 出る
    ↓
knowledge/ に昇格（長期記憶＝ルール化）
    ↓
全ロールが参照する「組織の知恵」になる


■ 日次: /session-wrap
  → その日の学びを memory.md に記録

■ 週次: /weekly-evolve
  → memory.md のパターン検出 → knowledge/ 昇格
  → 古い記録のクリーンアップ

■ 月次: /monthly-retro
  → knowledge/ 全体の棚卸し
  → GOAL進捗レビュー → 来月方針

この3層ループで、AIが自分で自分を改善し続ける。
人間が「これ覚えとけ」と言わなくても、
仕組みとして記憶が蓄積・整理・昇格される。
