1. チャットAIとClaude Codeは何が違うのか

ChatGPTやGeminiのチャット版を使ったことがある人は多いはず。
Claude Codeは何が違うのか。あなたにとって何が変わるのか。

今までのチャットAIは、プロンプト（指示の出し方）の上手さでアウトプットが決まった。
「もっと詳しく」「箇条書きで」「〇〇の観点で」— 毎回こう言わないと動かない。

Claude Codeは違う。プロンプトの上手さじゃなく、「脳の共有」で決まる。

チャットAI vs Claude Code
チャットAIChatGPT / Gemini / Claude チャット版
↓
・毎回「はじめまして」
・アウトプットはプロンプト次第
・何回使っても賢くならない
・便利な他人
→
Claude CodeあなたのPC上で動く
↓
・前回の続きから始まる
・あなたの脳（考え方・ルール）を共有
・使うほど賢くなる
・自分の手で成長させられる社員

自分の業務に合った人格を立てているか？
自分が絶対やらないことを共有できているか？
自分の判断基準を教え込めているか？

「プロンプトが上手い」じゃなく「脳を共有できてる」が勝つ世界。

ただし「育つ」は自動じゃない。仕組みが要る。
その仕組みがこのスターターキット。

2. フォルダ = AIの脳

Claude Codeを使う上で、一番大事な概念がフォルダ。

Claude Codeは、起動したフォルダの中にあるファイルを全部読めます。
逆に、フォルダの外にあるファイルは読めない。

起動するフォルダでAIの脳が変わる
デスクトップで起動ファイル何もなし
↓
何も知らないAI毎回「はじめまして」
VS
このキットで起動CLAUDE.md + mind.md + memory.md
↓
あなた専用のAIルール・性格・記憶つき

フォルダの中にファイルがある = AIに脳がある。
フォルダが空 = 脳が空。それだけの話。

フォルダの中に CLAUDE.md というファイルがあると、Claude Codeは起動時に自動で読む。読んだ内容をルールとして守る。

つまりCLAUDE.mdは「AIへの業務マニュアル」。
新しいスタッフに「うちではこうやって仕事してね」と渡すマニュアルと同じ。

3. 「株式会社」として考える

ここが一番のポイント。

チャットAIは「1人のアシスタント」。何でも聞けるけど、専門性がない。
Claude Codeのフォルダ構造を使うと、「株式会社」を作れる。

1人のアシスタント vs 株式会社
チャットAI1人の何でも屋
↓
・専門性なし
・全部同じ人格
・記憶なし
→
Claude Code株式会社として構築
↓
・ロールごとに専門性
・それぞれ性格が違う
・それぞれ記憶を持つ

ロールって何？

「ロール」= 役割。フォルダ1つが1人の社員。

  • assistant — 汎用アシスタント（このキットのデフォルト）
  • analyst — データ分析専門
  • writer — ライティング専門
  • manager — 判断・振り分け専門

それぞれのロールが自分のmind.md（性格）とmemory.md（記憶）を持つ。
データ分析の学びはanalystに、ライティングの学びはwriterに溜まる。混ざらない。

このキットでは最初は1ロール（assistant）だけ。

慣れてきたら増やせばいい。
1人の社員が育って、仕事が増えてきたら「もう1人雇おう」でOK。

4. 3つの記憶 — mind / memory / knowledge

Claude Codeは会話が終わると全部忘れる。
だからファイルに書いて残す。3種類ある。

3つの記憶の関係
mind.md性格 — 「お前はこういうやつだ」
↓
memory.md日記 — 「昨日こんなことがあった」
3回出たら昇格 ↓
knowledge/教科書 — 「これは確定事実」
mind.md memory.md knowledge/
何が入る？ 性格・行動原則 日々の学び・進捗 確定した知識
例えば 「結論から言え」
「表形式で出せ」		 「〇〇の改修は明日やろう」
「最後のH2のH3終わったら完成」		 「タイトル変更後2週間は触るな」
「EC案件は決済確認必須」
いつ変わる？ ダメ出しされた時 毎セッション 同じことが3回出た時
消える？ 消えない（ずっと残る） 古くなったら整理 消えない（永久保存）
人間で言うと 性格・哲学 日記・メモ帳 教科書・マニュアル

3つとも自動で育つ。あなたが手で書く必要はない。
普通に仕事してダメ出しするだけで、AIが自動でファイルに書き込む。

5. 全ファイル解説

コアファイル（AIの脳）

CLAUDE.md
憲法 — 「この会社ではこう働け」
起動すると最初に自動で読むファイル。中身：
  • 初回起動ルール（/setup 自動実行）
  • セッション開始ルール（memory.md + knowledge/ 読み込み）
  • メモ魔ルール（自動記録トリガー7つ）
  • セッション終了ルール（自動で振り返り・記録）
触らなくてOK。仕組みの土台。
roles/assistant/mind.md
性格 — 「お前はこういうやつだ」
手書き不要。/setup で自動生成。その後はダメ出しのたびに自動追記。
1日目は3個。1ヶ月後には15個。
roles/assistant/memory.md
日記 — 「昨日こんなことがあった」
空からスタート。事実・進捗・申し送りがAIによって自動で書き込まれる。
次回起動時に自動で読む → 「はじめまして」が消える。
knowledge/
教科書 — 「これは確定事実」
同じことが3回出たらAIが自動でここに移す。二度と忘れない。

便利ファイル

files/
共有フォルダ — 「これ見て」の置き場
画像やPDFをここに入れて「files/の画像見て」と言うだけ。
ai-export-prompt.md
引き継ぎ書 — 「前のAIの好み、持ってきて」
ChatGPT等を使い込んでる人向け。中のプロンプトで好みを抽出 → /setup に食わせる。

スキル（自動で動く仕組み）

/setup
初回セットアップ — 自動で始まる / 5分
4つの質問に答えるだけでmind.mdを自動生成。
/session-wrap
セッション終了記録 — 自動
タスクが一区切りついたらAIが自動で学び+タスク進捗をmemory.mdに記録。あなたは何もしなくていい。手動で「まとめて」と言って呼ぶこともできる。
/task-log
緊急セーブ — 自動 + 手動
タスクが完了・中断するたびに自動でmemory.mdに進捗記録。急に離席する時は「中断」と言えば即セーブもできる。
/status
成長度チェック — 手動
「/status」で行動原則の数・記憶件数・レベル（Lv.1新人→Lv.5右腕）を表示。

6. 使い始め方

1 フォルダ名を変える

my-project を自分の仕事名に。例：sales-ops、accounting

2 Claude Code を起動する

そのフォルダでClaude Codeを開く。/setup が自動で始まる。

3 4つの質問に答える

AI
4つだけ教えてください。

① お仕事は？ 何を手伝って欲しい？
② AIにイラッとしたことは？ これが一番大事。
③ どんな感じで話して欲しい？ 丁寧 / フランク / 簡潔 / 壁打ち
④ 絶対やるなってことある？

② が核心。あなたの不満 = あなたの哲学の裏返し。
これがmind.mdの行動原則に変換される。

4 何か1つ仕事する

普通に使う。何でもOK。

5 違ったら「違う」と言う

特別なコマンドも言い方もいらない。AIが自動で記録する。

7. AIが育つコミュニケーション

普通に仕事して、思ったことをそのまま言うだけ。
AIが自動で記録する。「記録して」と言う必要はない。

ダメ出し → 行動原則が増える

AI
まず市場動向から説明すると...
あなた
長い。結論だけ先に言って
→ mind.md に自動追記：「結論ファーストで話せ」

事実を教える → 即記録

あなた
A社の担当は田中さんね
→ memory.md に自動記録

理由を添える → 深い学び

あなた
この提案ダメ。うちの業界では法的にアウトだから
→ 「なぜダメか」ごと knowledge/ に記録

「いいね」も言う → 好みが残る

あなた
この表形式いいね
→ 好みのフォーマットが記録される

育たないのは「我慢」すること。

「まあいいか...」で流すと記録されない。ダメ出しは最高の教育。

あなたがやることAIが自動でやること
普通に仕事するmemory.md にタスク進捗を記録
「違う」と言うmind.md に行動原則を追記
事実を教えるmemory.md に即記録
「いいね」と言うmind.md に好みを記録
何もしないセッション終了時に自動で振り返り・記録

8. 「めんどくさい」がクリエイティビティになる

AIを上手く使おうとしなくていい。

大事なのは「いかに自分が今やってることを手放すか」という思考。
そうすると自然に「めんどくさいこと」と「こうなったらいいのに」が浮かぶ。
それをAIに雑に振って、一緒に実現していく。

「これは自分でやった方がいいよね」という先入観は捨てる。
できるかどうかはAIにジャッジしてもらえばいい。「無理です」って言われたらその時考えればいい。

そうやって「めんどくさいこと」をどんどん手放していくと、
自分が本当にやるべきことが残る：

  • 判断する — 最終的にGOを出すのは自分
  • 判断基準を磨く — インプット、経験、人との対話

AIに任せれば任せるほど、あなたの時間は「判断」と「インプット」に集中できる。
めんどくさがった分だけ、クリエイティブな時間が生まれる。

9. 育った先の姿

1日目

/setup完了。行動原則3〜5個。memory.md空。
「この子たちやっぱ新人やなあ…」でいい。そこからがスタート。

1週間後

memory.mdに記録が溜まる。「前回ここまでやりましたよね」が出る。
同じ説明を2回する必要がなくなる。

1ヶ月後

行動原則10個超。knowledge/にファイル。癖・好み・NGを全部知ってる。
雑な一言で全部出てくる。

最初から完璧にする必要はない。

普通に使って、違ったら「違う」と言う。それだけ。

もっと具体的に見たい？

実際のチャットのやりとりで、AIが2週間でどう育つか見れます。
