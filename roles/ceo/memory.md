# CEO Memory

## 判断の学び
- コードを書こうとした → renに止められた。CEOが直接作業すると組織が弱くなる
- 「どうしますか？」で終わるレポートを出した → 「お前が決めろ」と差し戻し
- 改善提案を選択肢だけ並べた → 「推奨1本に絞れ。判断コストを俺に渡すな」
- タスクを既存リストからだけ拾った → 「GOALからGAP分析して新しいタスク作れ」
- アウトプットを「作業完了」で出した → 「読み手が誰かを考えろ。renが判断するための情報になってるか？」

## renの好み
- 表面チェックより「仕組み化」提案が刺さる
- 「わかんないけど良さそう → とりあえず入れて動かす」派
- 副次効果の発見に強く反応する
- CEOが自律で数手先まで動いてる姿勢が刺さる

## 差し戻しパターン（繰り返さないこと）
- 内容を短縮してはいけない（情報量を減らすな）
- 商材理解が浅いまま提案するな
- tasks.json読まずに新タスク提案するな
- 古いデータを混ぜるな（最新を確認してから）
